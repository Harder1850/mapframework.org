# Reconciliation of prototype and governing versions

This document records material conflicts encountered while consolidating earlier website prototypes and the September 2026 governing MAP sources.

## 1. Parent brand: Relational Intelligence vs MAP Framework

**Conflict:** Earlier production-style prototypes were branded primarily as Relational Intelligence. Newer governing architecture places Purpose and recursive MAP above that layer.

**Resolution:** MAP Framework is the public parent architecture. Relational Intelligence remains a distinct conceptual foundation, with its own page and visual identity. It is not renamed MAP.

## 2. MAP acronym vs current process sequence

**Conflict:** Public naming uses **MAP Framework — Metamorphosis · Aletheia · Praxis**, while the current governing cycle explicitly includes **Understanding** and orders the cycle as `Aletheia → Understanding → Praxis → Metamorphosis → New Reality → Aletheia`.

**Resolution:** Preserve the established MAP name and descriptor, but publish the governing cycle exactly with Understanding as the explicit bridge between Aletheia and Praxis. Do not force the process into a three-step acronym when the current architecture is four-stage and recursive.

## 3. Older eight-step Relational Intelligence method vs governing MAP

**Conflict:** The Web on Demand prototype used Observe → Map relationships → Abstract structure → Find analogues → Find the delta → Locate leverage → Restore context → Act and learn as a main method.

**Resolution:** Preserve its strongest concepts inside the Relational Intelligence and applications material, but do not present it as the governing MAP cycle. The current governing architecture has authority.

## 4. Delta prototype dashboard vs empirical experiment

**Conflict:** Earlier prototypes displayed representative metrics (accuracy, detection, false/missed delta, calibration, timing) that could be mistaken for results.

**Resolution:** Remove fabricated aggregate values. The production Delta page is a functional, browser-local demonstration instrument with transparent cases. It computes only the current session's metrics and explicitly states that they are not research evidence. Research-grade infrastructure is documented separately.

## 5. ALIVE disclosure depth

**Conflict:** Some prototypes exposed a richer list of ALIVE mechanisms and research ideas. The publication/IP strategy requires sparse disclosure.

**Resolution:** The public ALIVE page is intentionally high-level. Exact data structures, learning/decay mechanisms, routing, proprietary evaluation, integration details, and unpublished findings remain out of the public repository.

## 6. Hosting/source-of-truth conflict

**Conflict:** ChatGPT Sites and Web on Demand were previously treated as possible production hosts.

**Resolution:** They are prototypes/reference sources only. GitHub is the sole production source; Cloudflare is production infrastructure; GoDaddy remains registrar. DNS remains unchanged until explicit cutover approval.
